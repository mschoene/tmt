# Symmetry Discovery — RL experiments

Code for discovering Lie group symmetries from offline RL datasets and validating them as
genuine dynamics symmetries via a soft equivariance penalty on a learned dynamics model.

## 1. Generate datasets

The base particle datasets used in the paper's examples below are already included
under `datasets/` (`particle_circle_2d_random_uniform.pkl`, `particle_circle_3d_random_uniform.pkl`).
To regenerate them from scratch, or to generate others:

```bash
# Custom environments — generates .pkl files under datasets/
python generate_datasets.py --env_name ParticleCircle2D-v0 --num_steps 200000

# MuJoCo environments — fetched on-demand via Minari
# Pass a Minari dataset ID as dataset_path (e.g. mujoco/reacher/expert-v0)
```

Datasets are stored as `.pkl` files with keys `episodes` (list of dicts with `observations`, `actions`, `rewards`, `terminals`) and `metadata`.

You can also mix datasets with different action-noise levels:
```bash
python mix_datasets.py
```

## 2. Symmetry discovery

All methods share the same interface: `--env_name`, `--dataset_path`, `--save_dir`, `--seed`, `--num_points`.

TMT-NN, TMT-KNN, and LieSD all share the continuous-generator-search machinery in
`jax_rl/networks/score_symmetry_discovery.py` (gap detection via `_pick_generator_count`,
widened-subspace orbit refinement, Lie-bracket closure). The defaults below are what was
actually used to produce the paper's results — you do not need to pass any of these flags
explicitly to reproduce them; they're listed here for transparency about what differs
between methods and what's shared.

Shared, identical across TMT-NN/TMT-KNN/LieSD (not CLI-overridable beyond what's shown):
- `--continuous_max_generators 8` — cap on candidate generators kept from the initial
  eigenvalue gap (`ContinuousDiscoveryConfig.max_generators`).
- `--continuous_abs_threshold_frac 0.1` — an eigenvalue only qualifies as "small enough to
  be a candidate symmetry direction" if it's below `0.1 * max(eigenvalue)`.
- `--continuous_closure_max_generators 16` — cap on the generator count after Lie-bracket
  closure.
- Orbit-refinement widened search: flow times `t ∈ {0.25, 0.5, 1.0}`, cosine-dedup threshold
  `0.9`, minimum `16` random restarts (`max(2 * (k+4), 16)`) — these are hardcoded in
  `orbit_refine_subspace` and `discover_continuous_symmetries`, not exposed as flags on any
  of the three scripts.

Differs per method (this is intentional, not an oversight — see
`--continuous_spectral_gap_min_ratio` default in each script):
- TMT-NN: `--continuous_spectral_gap_min_ratio 5.0`
- TMT-KNN: `--continuous_spectral_gap_min_ratio 1.5`
- LieSD: `--continuous_spectral_gap_min_ratio 1.2`

This is the minimum log-spaced ratio the winning eigenvalue gap must clear; below it, the
whole small-eigenvalue block is returned instead of the gap-selected subset (see
`_pick_generator_count` in `score_symmetry_discovery.py`).

### TMT-NN (score / denoiser-based)

```bash
python train_tmt_nn.py \
  --env_name ParticleCircle2D-v0 \
  --dataset_path ./datasets/particle_circle_2d_random_uniform.pkl \
  --save_dir /path/to/logs/tmt_nn/
```

Key hyperparameters:
- `--denoiser_num_epochs` (default 8000)
- `--sigma_min / --sigma_max` — noise scale range for the score model
- `--hidden_dims` — denoiser MLP architecture (default `256 256`)

Output: `<save_dir>/.../snapshots/discovered_symmetry_step0.{json,npz}`, auto-saved via
`representations.save_discovered_symmetry` — this is what `train_dynamics_model.py`'s
`--eq_symmetry_file` (below) loads.

### TMT-KNN

```bash
python train_tmt_knn.py \
  --env_name ParticleCircle2D-v0 \
  --dataset_path ./datasets/particle_circle_2d_random_uniform.pkl \
  --save_dir /path/to/logs/tmt_knn/
```

Same output format as TMT-NN.

### LieSD (Jacobian-based)

```bash
python train_liesd.py \
  --env_name ParticleCircle2D-v0 \
  --dataset_path ./datasets/particle_circle_2d_random_uniform.pkl \
  --save_dir /path/to/logs/liesd/
```

Key hyperparameters:
- `--dynamics_num_epochs` (default 2000)
- `--dynamics_lr` (default 1e-3)

Same output format as TMT-NN.

### LieGAN

```bash
python train_liegan.py \
  --env_name ParticleCircle2D-v0 \
  --dataset_path ./datasets/particle_circle_2d_random_uniform.pkl \
  --save_dir /path/to/logs/liegan/ \
  --K 2
```

Key hyperparameters:
- `--K` — number of Lie algebra generators to learn (fixed count, not gap-selected like the
  other three methods)
- `--mode` — `marginal` (default) or `conditional` GAN objective

**Output format differs from the other three methods**: LieGAN saves each of its `K`
candidates separately as `<save_dir>/.../snapshots/L_s_{k}.npy` / `L_a_{k}.npy` (plus
`scales.npy`, `W.npy`), *not* the `discovered_symmetry_step0.json` format — there's no
single "the" discovered generator the way there is for TMT-NN/TMT-KNN/LieSD. To use a
LieGAN result in the dynamics-model check below, pick a candidate `k` and call
`representations.save_discovered_symmetry(save_dir, step=0, env_name=..., n_s=..., n_a=...,
L_s=L_s[k][None], L_a=L_a[k][None])` to convert it into the loadable format first.

## 3. Dynamics-model equivariance check (Reacher)

This is how a discovered generator is validated as a genuine dynamics symmetry — not by
building it into a policy architecture, but by checking whether a **plain** MLP forward
dynamics model `f(s,a) -> delta_s`, trained with a soft penalty that supervises held-out
(rotated) predictions against the model's own prediction rotated by the generator, actually
generalizes to orientations held out of training. `--eq_lambda 0` (or no
`--eq_symmetry_file`) reduces to a plain dynamics-model fit with no penalty, for comparison.

```bash
python train_dynamics_model.py \
  --dataset_path ./datasets/reacher_expert.pkl \
  --eq_symmetry_file /path/to/logs/tmt_nn/.../snapshots/discovered_symmetry_step0.json \
  --eq_lambda 3.0 \
  --output_path /path/to/logs/dynamics_model/model.pkl
```

Then evaluate the trained model's one-step and open-loop rollout error at held-out
orientations (the model only ever sees phi=0 during training):

```bash
python eval_dynamics_model_orientation.py \
  --model_path /path/to/logs/dynamics_model/model.pkl \
  --dataset_path ./datasets/reacher_expert.pkl \
  --fixed_rollout_data ./datasets/orbit_aug_experiment/fixed_rollout_eval_data.npz
```

A generator that's a genuine symmetry drives the one-step/rollout error at held-out
orientations down toward the error at phi=0; a spurious one leaves it essentially
unchanged from the no-penalty baseline (`--eq_lambda 0`).

Key flags on `train_dynamics_model.py`:
- `--eq_symmetry_file` — path to a `discovered_symmetry_step0.json` (or the ground-truth
  generator, for a reference/floor comparison).
- `--eq_lambda` — penalty weight (`0` = no penalty, plain dynamics-model fit).
- `--eq_eps_min` / `--eq_eps_max` — range the finite-rotation angle `eps` is sampled from
  during training (default `[0, 2*pi]`).
